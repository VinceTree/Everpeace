## 当前：coding harness 的定位与编码完成质量

用户要求持续优化 harness 并明确定位，随后选择优先加强「编码闭环的可靠性与完成质量」。定位保持 DeepSeek 优先、Windows 优先，面向个人 Node/TypeScript 单包开发；CLI、exec 和 SDK 共用生产 runner，以当前证据衡量需求理解、实施、验证与恢复。

本轮从 Goal 生命周期入手，修复已复现的旧完成意图覆盖暂停、预算停止或新目标，以及同一轮重复 blocked 调用冒充三轮的缺陷。完成意图绑定目标和真实宿主回合；阻塞原因以摘要持久化，连续回合证据跨 Session 重开保留，恢复后重新审计。每个 step 和压缩边界提供完整原目标与当前状态，要求逐项核对当前证据，禁止以较小结果替代原任务。

验收包括真实 Agent 工具调度、Goal/JSONL 重开、不同阻塞与间断重置、旧记录兼容、暂停恢复和迟到完成、Plan 与原生／summary 压缩、既有取消／预算／清理结算，以及串行 typecheck → lint → test → build。状态机制与离线通过不代表真实模型语义审计可靠性或质量收益；不执行新的付费模型评测，不改展示版本或创建 Release。

后续继续沿共享 runner 的异常收尾与完成结算、模型终态和恢复债务检查实际缺口，先复现再修改。不把本轮 Goal 修复视为整个 harness 已完成优化。用户已明确授权本轮自动提交和推送；门禁通过后使用 `[skip publish]`，保留 CI，不创建 Release。

## 第一批：构建与检查可靠性

- 证明模块删除／改名后旧构建产物残留，修复为清理固定 `dist` 后重建；拒绝已有输出链接，编译失败不输出。
- 检查脚本共用当前存在的 Git 文件清单，覆盖未暂存删除、重命名、新增、ignored 和空输入；权限或读取错误不得被当作删除忽略。
- 同步开发指南、项目地图和双语 README，旧交接归档，移除当前状态中的过期授权与未提交描述。
- 定向回归后串行执行 typecheck → lint → test → build，首败停止；补充 docs、UI、workflow 和差异检查。通过后按本轮用户授权提交并推送当前分支，使用 `[skip publish]`，不关闭测试。

## 第二批：核心任务异常收尾

第一批完成推送后开始。沿请求、工具、最终验证、Session 持久化、Goal 和 Memory 结算检查取消、超时、清理失败与恢复；先证明问题再做聚焦修复，不以调查假设代替缺陷。验收要求异常后不重复执行或错误结算成功，恢复后保留验证债务。按改动范围运行回归和完整门禁。

MCP 启动前关闭事件修复已完成交付。本轮继续修复已复现的四类边界：团队验证收尾后的取消／超时检查、团队失败时根后台任务仍须清理并等待、恢复和冷快照的取消信号，以及无已知路径或 Git 不可用时的持久验证债务。通过 JSONL 重开、真实 GoalRuntime 和受控 worker 证明故障，再运行相关回归与完整门禁，提交并推送当前分支。

## 第三批：离线性能测量与优化

测量无凭据 CLI 新进程启动、长 Session 恢复、历史搜索冷／暖缓存和项目扫描。使用固定合成数据、相同原生组件与依赖，按两臂交错顺序记录逐次时间、正确性、读量、CPU 和峰值 RSS；绑定 fixture、源码与构建身份。只保留复测有效的优化，不减少扫描覆盖或削弱安全访问、取消和资源等待。

按实际成本合并 Session 的块内异步交接，并把有界源码候选读取限制在四路并发；字节预算和结果仍按文件顺序应用。补充取消、清理失败与缓存字节复核回归，保留无收益／退化候选的诊断，运行完整门禁后按授权提交、推送。协议见 [本地性能对照](benchmark/LOCAL_PERFORMANCE.md)，当前数字与收据只在 HANDOFF。
